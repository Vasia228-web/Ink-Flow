# Salvage з незавершеної переробки ядра (WIP від 2026-09-01)

Робоче дерево 1–22 вересня містило незакомічену переробку Core за специфікацією
`ink-flow-core-v2-spec.md` (муть, підмалевок, пензлі, полотна з фото, полотно 16×16),
яка розходилась із `docs/ink-flow-core-final.md`. Переробку відкочено до HEAD
(коміт «Відкат незавершеної переробки ядра v2»). Нижче — те, що з неї варте
повторного використання. Файли лежать поза `Assets/`, тож Unity їх не компілює;
це джерело для адаптації, а не код гри.

| Файл | Що робить | Як використовується далі |
|---|---|---|
| `PieceShape.cs` | Форма поліоміно: нормалізовані клітинки (мін. X/Y = 0), ширина/висота, вага видачі. `PieceDef` = форма + колір. | Береться майже без змін у нове ядро (`Core/Model/PieceShape.cs`); `InkColor` замінюється на `Pigment`. |
| `PieceCatalogData.cs` | Каталог форм 1–5 клітинок із вагами, розкладений по «стелі розміру» (для ескалації); `Pick(sizeCap, random)`; `Shape(id, weight, rows…)` — текстова розкладка форми. | Основа `PieceCatalogData` нового ядра. Ваги перевіряються прогонами, не копіюються сліпо. |
| `PlacementRules.cs` | `CanPlace`, `AnyFit`, `AnyPieceFits` (єдина перевірка живості), `TryFindHint`, `PreviewLines`, `CollectFullLines` (рядки знизу вгору, потім стовпці зліва направо). | Береться в нове ядро як `Core/Rules/PlacementRules.cs`. |
| `GreedyBot.cs` | Жадібний бот на реальних правилах Core з шумом «різних гравців»: оцінка = фарба на полотно + лишок у баках + чисті лінії + потенціал чистоти − фрагментація. | Замінює «10 ручних партій» після кроку 1: тисяча прогонів дає середню довжину партії, момент тиску й частку нечесних смертей. Евристику треба переписати під змішувач (немає муті/рецептів). |
| `InkFlow.Sim/` | Консольний прогонник (`dotnet run --project Tools/InkFlow.Sim -- --games 1000`), паралельний, з коридорами метрик і CSV. | Відроджується як `Tools/InkFlow.Sim` для нового ядра: та сама структура `Metrics.cs` (Distribution, Corridor), інша модель забігу. |

Що з WIP **не** береться і чому: `TankSet` (муть і переповнення баків — у документі немає),
`CanvasState`/`CanvasData`/`StarterCanvases` (полотно як сітка клітинок — Core пікселів
бачити не має; картинка = зони + маска), `MixColor` з рецептами на зону (змішування
йде за пропорцією в змішувачі), `LevelSession`/`StarterLevels` (режим «Рівні» відкладено),
`PlayfieldSession.UseBrush` (пензлів немає), заміна `InkColor` на Blue/Red/Yellow
(`InkColor` — палітра інтерфейсу, ігрова фарба — окремий тип), сейв v4
з `EndlessCanvasData`/`PhotoCanvasData` (інша схема).
